# Настройка окружения

1.	Убедитесь, что установлен Python 3.12+ (см. файл `pyproject.toml`).
2.	В корне проекта запустите установку зависимостей через Poetry:
`poetry install`
3.	Запуск приложения
Из той же папки, где лежит `main.py`, выполните:
4.	`poetry run python main.py [--provider PROVIDER] [--host HOST] [--port PORT] [--share] [--n_users]` 
Где:

	--provider, -p — имя API-провайдера для SectionChecker (по умолчанию yandex);

	--host, -H — адрес для Gradio (по умолчанию 127.0.0.1);

	--port, -P — порт (по умолчанию 7860);

	--share, -s — включить публичный шаринг через Gradio；
	
	--n_users, -n — максимальное количество одновременных сессий пользователей. По умолчанию, 50.

# Разметка рекомендаций
В сложных документах заголовки и структура могут быть крайне разнообразны: одни разделы оформлены как «1. …», другие — списками или подчёркнуты, иногда встречаются вложенные подразделы или маркеры разного вида. Из-за этого полностью полагаться на автоматические алгоритмы (фаззи-поиск, регулярные выражения и т. п.) надёжно не получается — часть заголовков «слетает», а границы блоков определяются неточно. Чтобы обойти эти ограничения и дать парсеру однозначные метки границ смысловых блоков, в текст рекомендаций вручную встраиваются специальные маркеры:
• `%intro%`…`%intro%` — область «введения» и общих требований;
• `%extra%`…`%extra%` — дополнительные сведения, не относящиеся к основным разделам;  
• `%split%` вставляется перед каждым названием раздела или подраздела, чтобы отделить один логический блок от другого
Парсер ищет эти маркеры в тексте рекомендаций, затем внутри каждого блока извлекает заголовок и содержимое, при необходимости проверяя его по эталонному списку секций.


# Структура и назначение файлов

## Общая структура

* Входная точка — main.py. 
Скрипт задаёт параметры запуска (провайдер LLM, хост/порт, возможность публичного шаринга) и строит веб‑интерфейс на Gradio для загрузки проверяемой инструкции, эталонной версии и рекомендаций; кнопка запуска вызывает generate_report из utils.report_generator
* Генерация отчёта — функция generate_report в utils/report_generator.py orchestration pipeline: извлекает тексты, загружает рекомендации из кэша, делит документы на разделы, запускает LLM‑проверку, вставляет результаты и сохраняет итоговый DOCX с временной меткой
Загрузка и очистка документов — класс DocumentLoader определяет тип документа (листок-вкладыш/ОХЛП), извлекает название препарата и очищает текст, используя библиотеку docling
* Интеграция с LLM — langchain_utils/section_checker.py выбирает одного из поддерживаемых провайдеров (YandexGPT, DeepSeek, OpenAI, Ollama) и содержит шаблоны промптов для поиска различий и проверки соответствия рекомендациям
* Парсинг разделов и рекомендаций — функции в utils/parsers.py делят текст по заголовкам и fuzzy‑сопоставлению, выделяя intro, extra и блоки %split%
* Семантическая сегментация — модуль semantic_segmenter.py реализует устойчивый алгоритм разбиения листка-вкладыша на 6 стандартных разделов без обращения к LLM
* Работа с DOCX — utils/docx_writer.py вставляет рекомендации в шаблон, заменяет плейсхолдеры и при необходимости подсвечивает различия в тексте
* Конфигурация — config_reader.py использует pydantic_settings для загрузки ключей API из .env, что позволяет легко менять провайдеров и скрывать секреты
* Дополнительные каталоги:
templates/ — DOCX-шаблоны отчёта; test_data/ — примерные входные файлы; results/ — целевая папка для сформированных отчётов (создаётся при запуске).

## Что важно знать

Предполагается, что документы бывают двух типов (ОХЛП и ЛВ). 

DocumentLoader автоматически различает листки-вкладыши и ОХЛП, подбирая соответствующие правила очистки и извлечения метаданных.

generate_report вызывает обработку документов, сегментацию, LLM-проверки, заполнение шаблона и сохранение.

Провайдеры LLM взаимозаменяемы. Достаточно передать --provider или установить переменные среды, чтобы переключиться между YandexGPT, DeepSeek, OpenAI или локальным Ollama.

DOCX-шаблоны должны содержать маркеры ({_RECOMMENDATIONS_}, placeholders с названиями) и таблицы; docx_writer заменит их на реальные данные и рекомендации.


## Разное

Функции docx_writer.py позволяют менять внешний вид и логику заполнения DOCX; полезно посмотреть, как формируется таблица сравнения и вставляются комментарии.

Скрипт debug_run.py - вспомогательный, он нужен для последовательной отладки. В штатном режиме не используется.
